## هدف

ثبت متمرکز دستور کار هر همکار، جلوگیری از کار تکراری، تعریف معیار پذیرش و فراهم‌کردن گزارش روزانه مبتنی بر شواهد قابل بررسی.

این اسناد، **دستورهای کاری ثبت‌شده** هستند؛ ثبت آن‌ها در GitHub به‌تنهایی به معنی ارسال خودکار به سرویس‌های بیرونی یا شروع کار آن ابزارها نیست. هر ابزار باید دستور مربوط را در همان سرویس دریافت کند و خروجی خود را با لینک Commit/PR یا شواهد بازتولیدپذیر گزارش کند.

## قواعد همکاری

1. هر وظیفه مجری اصلی مشخص دارد. همکاران دیگر فقط بازبینی یا نقد مستقل انجام می‌دهند، مگر واگذاری جدیدی ثبت شود.
2. هیچ‌کس بدون مجوز مالک، شاخه main را مستقیماً تغییر نمی‌دهد؛ تغییرات باید از شاخه مستقل و Pull Request عبور کنند.
3. در محدوده AC-004 هیچ SQL پیشنهادی به پوشه supabase/migrations منتقل یا روی پایگاه داده اجرا نمی‌شود.
4. هیچ Migration، تغییر داده واقعی، انتشار عملیاتی یا تصمیم حسابداری/مالیاتی با اثر مالی بدون تأیید صریح مالک مجاز نیست.
5. نتایج باید بین «اجرا شده»، «بررسی ایستا»، «پیشنهادی» و «اجرا نشده» تمایز قائل شوند.
6. صرفاً گزارش «انجام شد» معیار پذیرش نیست؛ لینک PR/Commit، نتیجه تست یا روش بازتولید لازم است.
7. موارد مبهم حقوقی و مقرراتی باید به‌عنوان تصمیم باز ثبت شوند، نه قاعده قطعی محصول.
8. هر یافته با شدت، مسیر فایل، اثر، روش بازتولید و معیار اصلاح ارائه شود.
