# پروتکل گزارش روزانه به مالک

- **شناسه:** OPS-DAILY
- **هماهنگ‌کننده:** ChatGPT
- **زمان‌بندی مورد نظر:** هر روز عصر، به وقت Europe/Amsterdam؛ زمان اجرای خودکار تقریبی است و تضمین دقیقه‌ای ندارد.
- **مخزن:** https://github.com/ziyamsvj-pixel/accounting

## هدف

در پایان هر روز، گزارش فارسی کوتاهی به مالک ارسال شود که وضعیت واقعی مخزن و خروجی قابل اثبات همکاران هوش مصنوعی را نشان دهد.

## منابعی که باید بررسی شوند

1. Commitهای تازه روی main و شاخه‌های کاری؛
2. PRهای تازه، ادغام‌شده، باز یا بسته‌شده؛
3. گفتگوها، Reviewها و رشته‌های بازبینی حل‌نشده؛
4. وضعیت GitHub Actions و نتیجه آزمون‌های مرتبط؛
5. تغییرات roadmap، changelog و تصمیم‌های D-007/D-008؛
6. لینک‌های تحویل اعلام‌شده از سوی همکاران، در صورت ثبت در GitHub.

## قواعد امانت‌داری گزارش

- فقط فعالیت قابل ردیابی را به همکار نسبت بده؛ نام نویسنده Commit، مشارکت‌کننده PR یا نظر ثبت‌شده را با هم اشتباه نگیر.
- اگر انتساب قطعی نیست، بنویس «مجری قابل احراز نیست».
- وضعیت تست را از روی نتیجه واقعی CI ثبت کن؛ سبز بودن یک job به معنی آماده‌بودن PR برای ادغام نیست.
- کار برنامه‌ریزی‌شده یا دستور ثبت‌شده را با کار اجراشده یکی ندان.
- برای هر مورد مهم، پیوند مستقیم GitHub ارائه کن.
- هیچ تغییری در مخزن ایجاد نکن، PR ادغام نکن، و Migration یا عملیات روی داده واقعی اجرا نکن.
- اگر ابزار یا مخزن در دسترس نبود، محدودیت را صریح گزارش کن؛ برای پرکردن خلأ، نتیجه حدس نزن.

**سطح اطمینان گزارش:** بالا/متوسط/پایین و دلیل آن.

## معیار کیفیت

گزارش باید کوتاه، قابل اقدام و مستند باشد. اگر در آن روز Commit یا تحویل قابل مشاهده‌ای رخ نداده است، صریحاً بنویس «تغییر قابل اثباتی در GitHub مشاهده نشد»؛ این را به معنی عدم انجام هیچ کاری در ابزارهای خارج از مخزن تعبیر نکن.
